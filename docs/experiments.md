# 实验与结果记录规范

## 固定条件

首版主平台为 RTX 3090 24 GiB、Qwen3-4B BF16、TP=1、16K 最大上下文。冻结 vLLM/模型/tokenizer revision、attention backend、Graph、chunked prefill、batch、KV dtype、缓存容量及请求生成方式。配置变化后建立新基线。

已验证的起步参数为 `configs/baseline-3090.json`：最多 4 条活跃序列、2,048 batched tokens、显存比例 0.85、APC/async/chunked prefill 开启、eager。等待窗口 16 与活跃序列上限是不同参数。

基于模型结构估算，BF16 KV 每个独立 token 约 144 KiB，一条完整 16K 序列约 2.25 GiB；共享前缀可以复用块。实际容量以启动后读取的 KV 配置为准。本次 readiness 为 88,848 tokens，不能据此假定任意并发与长度组合均可无抢占运行。

## 正确性门槛

正式性能实验前，先通过真实 Scheduler replay 构造 B/C 反例，记录原生顺序、改序后的准入、命中块、实际 prefill 和重算 tokens。确认缓存压力确实导致了不同路径；仅有缓存命中增加不足以证明调度收益。

原生回归覆盖项目方案中的关闭等价、稳定排序、窗口与屏障、保护顺序、只读评分副作用、请求生命周期和异步占位。不得用纯列表排序测试替代 native Scheduler 验证。

## 负载矩阵

| 类型 | 用途 | 需要控制 |
|---|---|---|
| 已知冷热交错的 B/C 场景 | 解释准入顺序如何改变复用机会 | 队列到达、A 的生命周期、B 的块需求 |
| 多个共享前缀族 burst | 检查多个可复用前缀竞争 | 前缀族规模、burst、后缀长度和输出长度 |
| 持续冷热混合流量 | 观察等待保护与稳定性 | 到达率、冷热比例、前缀分布和持续时间 |
| 负对照 | 判断额外排序是否造成成本 | 充足缓存、全冷请求、并发 1 分别运行 |

首先使用公开合成文本，再补多轮共享系统前缀重放。相同前缀必须落实到相同 tokenizer 后的 token IDs。校准集、测试集与随机 seed 分开保存，测试集不再调参。

## 对照与统计单位

主要对照为原生 FCFS、`prefix`、`guarded`；另做原生类与插件 `off` 的等价/成本对照。SGLang 作为机制参考，首版不做跨引擎性能竞赛。

关键场景每轮至少 500 请求，五组交替配对运行，以整轮运行作为重复单位。尽量在同一次 GPU 分配、同一节点连续完成配对组，记录设备、资源与并发干扰。冷启动、模型加载和 warmup 独立记录，不混入稳态样本。固定窗口 16；只有校准集支持时从 8/16/32 选择，选择后冻结。

所有模式使用相同到达表；用有明确到达率的回放检查排队，避免仅闭环并发掩盖等待。负载生成与计时在计算节点执行，Mac 仅用于控制和查看。

## 指标

主指标为 TTFT p95，同时保留：

- 实际执行的 prefill tokens，包含抢占重算；不能只用输入长度减 cached tokens 推断全部工作量。
- cached tokens、吞吐、TPOT、取窗口/评分/排序成本。
- cache-hot 与 cache-cold 各自的 TTFT 分布、等待、被越过次数。
- 失败、取消、未完成请求和运行截止条件。

prefill、TTFT 与等待的采集点必须在实现前定义，并区分客户端到达、引擎入队、准入、首 token 和结束。失败及未完成请求不得从报告分母静默移除。报告每轮结果、配对差异与运行波动；缓存命中率提升不能直接写成推理加速。

## 目录和记录契约

每轮输出到独立 `runs/<experiment>/<run-id>/`，包含 config、上游与项目 commit、环境、workload/seed/到达表、请求 trace、引擎日志、统计结果和解释。完整运行目录默认不提交。

公开数据通过明确的导出生成到新的 `evidence/<run-id>/`，移除集群身份和敏感路径，保留用于结论的数值、测量定义及来源哈希。原始 private trace 必须保留，不覆盖旧记录。当前 readiness 导出脚本只处理已有最小验证 schema；正式实验需要另行设计并验证 trace schema。

当前 readiness 的单次调用耗时只用于排查运行状况，没有配对重复和完整到达/首 token trace，不用于 TTFT 或加速结论。
