# 项目工作流

以仓库 `AGENTS.md`、当前代码、技术文档及本轮任务的验收条件为准。用户的明确目标与已授权范围优先；本技能不扩展外部操作权限。

按任务读取 [工作流](../../../docs/workflows.md) 的对应部分，不必把三种模式全部执行一遍。

- **多 agent 协作**：有独立子问题时使用。主 agent 先定义目标、验收、文件所有权与资源预算，再分配调查、反例或审查任务。共享文件系统不提供自动隔离；并行写代码前明确分支/worktree 与归属。协调者整合并复核结果，单 GPU 实验统一串行。使用 [任务模板](../../../docs/templates/task.md) 与 [交接模板](../../../docs/templates/handoff.md)。
- **开源实现调研**：围绕当前阻塞搜索并打开一手源码、测试或官方文档；记录固定 commit、函数、日期、PR 状态及迁移差异。使用 [调研模板](../../../docs/templates/research.md)，将不可访问或尚未验证的内容标清。调研不得绕过 M1 原生反例。
- **实验与验收**：使用工作流中的证据采集与核验入口，保留失败、超时及未执行记录。区分 local、native、gpu、performance 层级；命令成功与证据完整不等于验收通过。按真实标准逐项审查后，将结论、证据及限制写入交接或技术记录；技术能力变化时更新 `docs/state.md`。

保留已有未提交修改；执行者只改分配的文件。需要新增用户聊天、定时任务或外部消息时，遵循现有用户授权，不由本技能推断授权。完整原始运行留在忽略的 `runs/`，公开材料沿用显式导出约定。
